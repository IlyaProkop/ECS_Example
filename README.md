# Arena — Unity / Morpeh ECS

Рабочий прототип по [тестовому заданию](tz.txt) на разработку игровых систем. Игрок входит на арену, сражается с конечной волной врагов и получает результат боя. Победа приносит валюту, прогресс сохраняется между запусками.

**Стек:** Unity 6000.3.6f1, C#, Morpeh ECS, URP, Input System, uGUI. Графика построена на примитивах.

[Видеопрохождение — 45 секунд, 1080p](media/gameplay.mp4): стрельба и способность, победа, повтор боя, поражение и возврат в меню. Записано через сценарий PlayMode до добавления панели слотов; без звука.

## Быстрый запуск

1. Откройте проект через Unity Hub в **Unity 6000.3.6f1** и дождитесь импорта пакетов.
2. Откройте сцену [Bootstrap.unity](Assets/Scenes/Bootstrap.unity) и нажмите Play.
3. Выберите **Начать бой** и пройдите через зелёный вход на арену.

| Действие | Управление |
| --- | --- |
| Движение | WASD / стрелки |
| Стрельба по ближайшему врагу | Удерживать ЛКМ / J |
| Основная способность | Space / E / 1 или кнопка панели |
| Дополнительные способности, если настроены | 2–4 или кнопки панели |
| Повтор боя / возврат в меню | Кнопки экрана результатов |

На арене появляются 12 врагов двух типов. Уничтожение всех врагов завершает бой победой, потеря здоровья — поражением. Препятствия блокируют движение, снаряды и площадной урон. Ударная волна также временно повышает скорость и броню героя.

## Что реализовано

| Часть задания | Реализация |
| --- | --- |
| Damage / Health | Общий пайплайн урона для игрока и врагов с модификаторами крита и брони |
| Контроллер игрока | Перемещение, базовая атака и активная AoE-способность с независимыми перезарядками |
| Статистика | Время боя, нанесённый и полученный урон, убийства, атаки, применения способности, криты и монеты |
| Прогрессия | Награда за победу: 100 валюты и собранные монеты |
| Save / Load | Интерфейс хранилища и JSON-реализация с резервной копией и обработкой ошибок записи |
| Состояния игры | Инициализация → ожидание входа → бой → результаты → мета-экран |

Дополнительно: общая стрельба героя и врагов, смена оружия во время боя, прямые и самонаводящиеся снаряды, горение, бафы/дебафы и пул снарядов. Основная арена использует базовую стрельбу; дополнительные конфигурации находятся в [Examples/Combat](Assets/Game/Examples/Combat).

## Архитектура

| Сборка | Ответственность |
| --- | --- |
| `Game.Domain` | Определения, правила расчёта урона, контракты ввода и снимки состояния |
| `Game.Authoring` | ScriptableObject-настройки и преобразование в неизменяемые определения сессии |
| `Game.ECS` | Симуляция, компоненты и системы Morpeh; внешний доступ через `GameSession` |
| `Game.Application` | Переходы между состояниями, прогрессия и контракты сервисов |
| `Game.UiModel` | Модели состояния и команды интерфейса, подход MVVM-like |
| `Game.Presentation` | Unity lifecycle, устройства ввода, отображение, uGUI и файловое хранилище |

Симуляция работает с фиксированным шагом 1/60 секунды и не хранит ссылки на GameObject, Transform или UI. Представление передаёт ввод и получает снимки значений. Системы получают необходимые зависимости через конструкторы; компоненты содержат только значения, рабочие коллекции принадлежат сессии и системам.

Оружие, выбор цели, движение снаряда и эффекты попадания разделены. Урон проходит через общий пайплайн, а статистика учитывает фактически снятое здоровье. UI получает подготовленное состояние из ViewModel и не изменяет игровые правила.

**С чего начать просмотр кода:**

- [GameSession](Assets/Game/Scripts/ECS/Core/GameSession.cs) — граница симуляции, фиксированный шаг и время жизни мира.
- [GameplayInstaller](Assets/Game/Scripts/ECS/Core/GameplayInstaller.cs) — композиция систем и порядок выполнения.
- [DamagePipeline](Assets/Game/Scripts/Domain/DamagePipeline.cs) — расширение правил расчёта урона.
- [GameFlowController](Assets/Game/Scripts/Application/GameFlowController.cs) — бой, результаты, повтор и меню.
- [HudViewModel](Assets/Game/Scripts/UiModel/HudViewModel.cs) — подготовка состояния интерфейса.
- [AbilityBarViewModel](Assets/Game/Scripts/UiModel/AbilityBarViewModel.cs) — коллекция слотов, независимые cooldown и команды активации.

## Настройки и расширение

Баланс задаётся в [GameConfig.asset](Assets/Game/Resources/GameConfig.asset); быстро открыть его можно через `Game → Select balance config`. Оружие, снаряды, статусы и способность настраиваются отдельными ресурсами. Новая сессия получает проверенные определения, независимые от последующего редактирования этих ресурсов.

Прогресс хранится в `Application.persistentDataPath/progress.json`, резервная копия — `progress.json.bak`.

Подробнее — [схема архитектуры и границы ответственности](docs/overview.md).

## Проверка и сборка

Движение больших групп использует Jobs/Burst. После исправления направленного дрейфа и ограничения сближения врагов в Release на Ryzen 9 9950X / RTX 5070 Ti при 1080p на 10 000 живых врагов p99 кадра составил 7,83–10,16 мс: два запуска на 1200 кадров, один фиксированный шаг на кадр, увеличенная арена и до 120 HP-индикаторов. Два кадра превысили 16,67 мс, максимум — 24,90 мс. Это измерение конкретной нагрузки, а не гарантия отсутствия просадок. Условия, проход, массовая стрельба и воспроизведение — в [описании профиля](docs/overview.md#сценарии-скопления-и-стрельбы).

Тесты доступны через `Window → General → Test Runner`: EditMode проверяет игровые правила, навигацию и границы модулей, PlayMode — победу, поражение, повтор боя и возврат в меню. Для автоматической проверки отдельного снимка исходников и Windows-сборки запустите `python tools/verify.py` (Python 3.10+, Git, Unity и Windows Build Support). Требования и этапы — в [описании проверки](docs/overview.md#проверка).

Для Windows-сборки установите модуль Windows Build Support и выберите `Game → Build Windows prototype`. Результат появится в `Builds/Windows`; для запуска нужна вся папка плеера.

Сборки, журналы и рабочие отчёты остаются локально и исключены из Git. Регрессионные тесты и инструмент проверки включены в репозиторий.
